# Go CLI Rewrite — Phased Plan

Rewrite the Appwrite CLI from TypeScript/Bun to Go, generated by this repository the
same way the TypeScript CLI is today.

Read [README.md](README.md) before touching anything. It is the operating manual;
this file is the roadmap.

---

## 1. Why

### 1.1 What exists today

The CLI is generated into `examples/cli/` from `templates/cli/` by
`src/SDK/Language/CLI.php` (1,169 lines, extends `Node`).

| Measure | Value |
|---|---|
| Hand-written TypeScript in `templates/cli/` | ~27,000 LOC |
| Of which `lib/commands/` | ~12,900 LOC |
| Generated service files | 23 services, 720 KB, **608 commands**, 2,912 flags |
| Runtime npm dependencies | 23, including one native module |
| Shipped bundle (`dist/`) | 9.5 MB |
| Distribution | npm (`dist/cli.cjs` on Node 18) + `bun build --compile` binaries |

Largest hand-written units, in descending order — these are the rewrite's real cost:

| File | LOC | What it is |
|---|---|---|
| `lib/commands/push.ts` | 4,380 | Deploy state machine: diffing, approval, upload, polling |
| `lib/config.ts` | 1,488 | `appwrite.config.json` model and mutation |
| `lib/questions.ts` | 1,363 | Every interactive prompt |
| `lib/utils.ts` | 1,293 | Version checks, browser open, git clone, misc |
| `lib/commands/pull.ts` | 1,206 | Remote → local sync |
| `lib/commands/utils/attributes.ts` | 1,138 | Schema reconciliation |
| `lib/commands/init.ts` | 1,133 | Scaffolding |
| `lib/parser.ts` | 1,077 | Output rendering, redaction, error reporting |
| `lib/response-config.ts` | 940 | Per-resource display config |
| `lib/commands/utils/deployment.ts` | 784 | tar.gz packaging |
| `lib/completions.ts` | 577 | Hand-rolled bash/zsh/fish/pwsh completion |

### 1.2 Where the time actually goes

Be honest about the bound on the upside. Three buckets:

1. **Process startup — dominant for the common case.** A 9.5 MB bundle, 608 commander
   registrations at import time, to run one subcommand. Also why tab-completion lags:
   every completion request pays full startup.
2. **`push` — the only real compute.** `packageDirectory()` in `deployment.ts:565`
   walks the tree with JS gitignore matching, writes a `tar.gz` to a temp file, then
   `fs.readFileSync`s **the entire archive into a Buffer** and wraps it in a `File`.
   Fan-out is `Promise.all` over a hand-rolled `Pools`.
3. **Everything else** is network-bound (paginated API calls) or human-bound
   (inquirer prompts). A rewrite changes nothing here. Do not promise that it will.

### 1.3 Why Go and not Rust

On startup — the headline metric — they tie: ~1 ms (Rust) vs ~2–3 ms (Go runtime init).
Both are indistinguishable from the 206 ms being replaced. Rust's real advantages
(no GC pauses, zero-cost abstractions over CPU-bound loops) target workloads this CLI
does not have.

Go wins on what actually differs:

- **The workload is I/O fan-out over shared mutable state.** `push`'s deploy-poll-report
  loop maps onto goroutines + `errgroup.SetLimit` almost 1:1. In Rust the same code
  carries tokio plus `Arc<Mutex<_>>` around the spinner, config, and pool — real
  friction for zero throughput gain on network-blocked work.
- **A first-party Go SDK already ships** from this generator (`templates/go/`). The Rust
  SDK (`templates/rust/`) is newer. Choosing Rust means hardening the client SDK and
  rewriting the CLI at once — two projects.
- **Cross-compilation.** `GOOS`/`GOARCH` covers all six targets, including
  `windows-arm64`, with no per-target toolchain. Rust cross-compilation plus the macOS
  codesign check already in `install.sh.twig:106` is materially more setup.
- **Contributors.** Appwrite is a PHP/TS shop and the CLI takes community PRs. Go is a
  week. Rust's async + lifetimes is a permanent tax on every contributor.

Rust's only concrete win is binary size (~8–15 MB vs ~20–25 MB). Both are a fraction of
the current Bun binaries, so it does not decide anything.

### 1.4 Expected impact

Phase 0 has now measured the first two rows against a real spike — see
[BENCHMARKS.md](BENCHMARKS.md). The rest stay targets until Phase 6.

| Metric | Today | Target | Phase 0 spike |
|---|---|---|---|
| `appwrite --help` | 206 ms | < 10 ms | **5.0 ms** (41×) |
| Tab-completion round trip | full startup per request | < 10 ms | 5.1 ms |
| `push` of a large site (wall clock) | 7.00 s / 369 MB tree | −20 to −40 % | **−56 %** |
| `push` peak RSS | 421 MB, grows with archive | O(chunk size) | **102 MB, flat** |
| Binary size | ~60–90 MB (Bun) | ~20–25 MB | 2.9 MB (no logic yet) |
| Native modules to codesign | 1 (`@napi-rs/keyring`) | 0 | 0 |

Unchanged: `pull`, `types`, `generate`, and anything paginating the API.

### 1.5 Cost

3–6 months. This is a rewrite, not a port. `push.ts` and `attributes.ts` are intricate
state machines where the logic *is* the product, and they have no test coverage beyond
the e2e suite. Budget accordingly.

## 2. Target architecture

### 2.1 Generator side

```
src/SDK/Language/GoCLI.php        ← new Language class, extends Go
templates/go-cli/                 ← new template tree
examples/go-cli/                  ← generated output (gitignored)
```

`GoCLI` extends `Go`, not `CLI`. It inherits Go type mapping, keywords, and
`godocComment`; it reimplements the CLI-specific Twig helpers.

These nine helpers in `CLI.php` are the CLI's codegen contract. Every one needs a Go
equivalent in `GoCLI.php`, and each is a place where behaviour can silently drift:

| Helper | `CLI.php` | What it decides |
|---|---|---|
| `cliQueryConfig` | `:420` | Which of `--filter/--sort-*/--limit/--offset/--cursor-*/--select` a method gets, and the `--queries` help text |
| `cliServiceScope` | `:276` | Header-scoped services (Organization, Project) and their ID flag |
| `cliTopLevelAliases` | `:307` | Root-level promoted commands |
| `cliCommandTargets` | `:348` | Service subcommand + hidden/standalone variants |
| `cliFallbackHelpers` | `:383` | Which `console-fallback` helpers a service imports |
| `hasCliQueryParam` | — | Whether a service needs query imports |
| `getCliOption` | — | Flag syntax, description, parser |
| `getCliVarName` | — | Action-handler variable name |
| `getCliArgExpression` | — | Argument passed to the SDK call |

Also carried over: `consoleIgnoreFunctions` / `consoleIgnoreServices` (`CLI.php:20–70`),
`TOP_LEVEL_COMMANDS` (`:244`), `CONSOLE_FALLBACK_METHODS` (`:256`), `SCOPE_FACTORIES`
(`:229`), and the exclusion list in `example.php:267–308`.

## 3. Invariants

These must not change. A rewrite that improves the UX is a rewrite nobody can adopt.
Any deliberate break needs its own PR, its own changelog entry, and sign-off.

1. **Every flag name, shorthand, and alias.** 608 commands and 2,912 flags worth. Phase 1 produces a
   machine-checkable snapshot of these; Phase 4 diffs against it.
2. **`appwrite.config.json` schema.** Read and written byte-compatibly. Existing project
   files must work untouched, in both directions (a Go `push` after a TS `pull`).
3. **Exit codes.**
4. **`--json` and `--raw` output**, byte-for-byte. These are scripted against.
5. **Secret redaction.** `SENSITIVE_KEYS` in `parser.ts:54`, `HIDDEN_VALUE`,
   `--show-secrets`. A regression here is a security bug, not a formatting bug.
6. **Global config location and format** (credentials, endpoint, cookies).
7. **`x-sdk-*` headers.** Asserted by `Base::getExpectedSdkHeaders()`.
8. **Install paths.** `install.sh`, `install.ps1`, scoop manifest, Homebrew tap all keep
   their current install locations and binary names.

Two things are explicitly **not** invariants:

- **Human-readable table output.** Keep it recognisable, but it is not part of the
  contract.
- **Keyring credential interop.** Reading a token written by the TypeScript binary is
  a convenience, not a requirement. If the Go binary cannot find it, the user logs in
  again — an acceptable one-time cost. See Phase 0 item 3.

**Goal:** prove the startup and `push` numbers before committing months. Kill the

**Entry:** none.

**Outcome:** both gates cleared by a wide margin — startup 41× (gate: 5×), `push`

### Phase 1 — Generator scaffolding ✅ COMPLETE

**Goal:** `php example.php go-cli` produces a Go module that compiles and runs
`--help`. No real commands yet.

**Entry:** Phase 0 exit met.

**Work:**

1. `src/SDK/Language/GoCLI.php` extending `Go`. Implement `getName()`,
   `getKeywords()`, `getIdentifierOverrides()`, `getFiles()`, `getTypeName()`,
   `getParamDefault()`, `getParamExample()`.
2. Port the nine Twig helpers from §2.1. Port them *as behaviour*, not as text —
   `cliQueryConfig`'s branching (`CLI.php:420`) is subtle and the collision checks
   against parameter names matter.
3. `templates/go-cli/` with `go.mod.twig`, `main.go.twig`, `internal/cmd/root.go.twig`,
   and a placeholder service template.
4. Register every file in `getFiles()`. **A `.twig` with no `getFiles()` entry is
   silently never generated** — the most common failure in this repo.
5. Add the `go-cli` block to `example.php`, mirroring the CLI block's exclusion list
   (`example.php:267–308`) exactly.
6. **Flag snapshot tool.** A script that walks `examples/cli/lib/commands/services/*.ts`
   and emits `templates/go-cli/internal/cmd/testdata/command-surface.json`: every command path, flag, shorthand,
   default, required-ness, alias, and hidden state. This artifact is the contract for
   Phase 4. Build it now, from the TypeScript, while the TypeScript is still the truth.

**Exit:**
- `php example.php go-cli` succeeds.
- `cd examples/go-cli && go build ./... && ./go-cli --help` works.
- `composer refactor:check` and `composer lint-twig` pass.
- [x] `command-surface.json` committed, with 608 commands and 2,912 flags in it.
- [x] The generated Go tree matches it **exactly**: 608/608 command paths, zero flag
      differences, zero required-flag differences, zero hidden-state mismatches.

**Findings:**
- The nine helpers are now a shared trait, `Language\Concern\CliCommandSurface`, used by
  both `CLI` and `GoCLI`. Drift is structurally impossible rather than merely discouraged.
- Flag names and Go identifiers need **separate** keyword lists. `FLAG_RESERVED_KEYWORDS`
  in the trait is frozen and shared, because a flag name is public surface;
  `GO_RESERVED_IDENTIFIERS` in `GoCLI` only renames private variables. Deriving flags from
  Go's keywords would have silently changed the CLI's flag surface.
- Generated Go is **formatted after generation** with `gofmt -w`, not emitted
  pre-formatted. Twig cannot reproduce gofmt's struct-field alignment, and gofmt is
  idempotent, so formatting belongs in the build rather than the template.

**Risk:** `GoCLI extends Go` inherits `Go::getFiles()`. Override it completely; do not
merge. Check `Go.php:63` for what you are replacing.

### Phase 5 — Stateful commands

**Goal:** `init`, `pull`, `push`, `run`, `types`, `generate`, `update`. The bulk of the
remaining work, and the part with real behavioural risk.

**Entry:** Phase 4 exit met. Do not start earlier — you need the harness to catch what
you break. (Phase 4 now precedes this phase; see the note there.)

Sequence deliberately, easiest first, so the hardest lands with the most infrastructure
in place:

**5a — `update`** (`update.ts`, 460). Self-update. Small, self-contained, and it must
handle updating *from* a TS install *to* a Go binary.

**5b — `types` and `generate`** (`types.ts` 236, `generate.ts` 206, `generators/` ~750,
four `.hbs` templates). Handlebars → `text/template`. Output must be byte-identical;
`CLI_TYPEGEN_RESPONSES` asserts this.

**5c — `run`** (`run.ts` 434, `emulation/docker.ts`, `emulation/utils.ts`). Docker
subprocess orchestration. Shells out either way, so it is mostly plumbing.

**5d — `init`** (`init.ts` 1,133, `questions.ts` already ported in Phase 2). Scaffolding
and prompts. Includes the git-clone-from-templates path in `utils.ts:1095`.

**5e — `pull`** (`pull.ts` 1,206, `attributes.ts` 1,138, `database-sync.ts` 220,
`schema.ts` 155). Remote → local. Attribute reconciliation is the hard part.

**5f — `push`** (`push.ts` 4,380, `deployment.ts` 784, `pools.ts` 355,
`change-approval.ts` 193, `error-formatter.ts` 417). The largest single unit in the
project. Split it: `internal/cmd/push/` with one file per resource type, plus a shared
diff/approve/deploy core. `errgroup.SetLimit` replaces `Pools`.

**Exit per sub-phase:**
- Full e2e suite green.
- Differential test green.
- Manual smoke against a real Appwrite project, recorded in the PR.

**Exit for the phase:** feature parity. `command-surface.json` fully satisfied.

**Risk:** `push.ts` has no unit tests. Write characterisation tests against the TS
implementation *first* — capture its behaviour on a set of fixtures — then make Go
satisfy them. Do not port 4,380 lines on faith.

### Phase 6 — Performance

**Goal:** hit the §1.4 targets and prove it.

**Entry:** Phase 5 exit met. Correctness first. Do not optimise into an unverified
implementation.

**Work:**

1. `pprof` the startup path only if it regressed past the Phase 0 measurement of
   5.0 ms. Cobra tree construction is **not** the bottleneck — that is settled; do not
   re-litigate it with lazy registration.
2. Streaming deploy: `archive/tar` → `pgzip` → `io.Pipe` → multipart body. No temp
   file, no full-archive buffer. Phase 0 proved this holds peak RSS flat at ~102 MB
   while the archive doubles from 95 MB to 190 MB. **Use gzip level 9** — `node-tar`
   effectively defaults to 9, and level 6 silently uploads ~3 % more bytes.
3. Tune `errgroup.SetLimit` against the polling behaviour. The TS `Pools` debounce
   logic (`push.ts:2864`) encodes tuning that was learned the hard way — read it before
   picking a number.
4. Trim binary size: `-ldflags="-s -w"`, audit the dependency tree.
5. Extend `BENCHMARKS.md` with before/after for every §1.4 row, on the same hardware
   as Phase 0.

**Exit:**
- Every §1.4 target met, or a written explanation of which was not and why.
- A CI benchmark job that fails on a startup regression beyond a threshold.

   hypothetical: `listStages`, `updateStage` and `approve` are excluded from the
   TypeScript CLI today purely because the released npm package trails the spec

6. **npm shim.** `appwrite-cli` on npm must keep working: a thin package whose

   for a large number of users.
7. Shell completions generated by cobra, installed by the installers.
8. `.github/workflows/` for build, sign, and release.

**Exit:**
- All six binaries build, sign, and install cleanly in a clean VM per platform.
- `npm i -g appwrite-cli` installs a working Go binary.
- Completions work in bash, zsh, fish, and PowerShell.

### Phase 8 — Rollout

**Goal:** switch over without stranding anyone.

**Entry:** Phase 7 exit met.

**Work:**

1. Pre-release channel. Both CLIs generated and shipped; Go behind an explicit install
   flag or a `-rc` tag.
2. Dogfood internally for one full release cycle. Track: config compatibility, `push`
   on real projects, CI pipelines using `--json`.
3. Migration notes covering anything that did change, however small. If credentials do
   not carry over, say so plainly at the top — one line, with the `login` command to
   run. Headless CI users need to know before they upgrade, not after a pipeline fails.
4. Flip the default. TypeScript CLI stays installable for at least one minor cycle.
5. Deprecate: remove `templates/cli/`, `src/SDK/Language/CLI.php`, the three
   `CLIBun*Test.php` files, and the `cli` block in `example.php`. Rename `go-cli` → `cli`
   throughout, so the ecosystem sees no rename.

**Exit:**
- Go CLI is the default install on every channel.
- TypeScript CLI removed from the generator.
- `AGENTS.md` updated: the SDK table, the inheritance table
  (`Node → CLI, ReactNative` loses `CLI`), and the lockfile rule for `templates/cli/`.

**Risk:** step 5 is the one that cannot be undone cheaply. Do not start it until the Go
CLI has been the default for a full release cycle with no rollback.
